# CHG-000 · PRD com fonte única e trabalho por PR

**Estado:** aplicado (PR `docs/chg-000`); proteção do `main` por ligar · **Owner:** Tomás · **Data:** 2026-10-29
**Tipo:** processo, CI e definições do GitHub. Sem alteração funcional e sem alteração ao PRD.

## Problema
1. O PRD existia em três sítios editáveis (repo, pasta Clipping App, Doc no Claude), e uma sessão de implementação podia alterá-lo dentro de um commit de código sem ninguém dar por isso (AGENTS §11 e PRD §28 proíbem, nada verifica).
2. Cada push das sessões vai direto para `main` e para produção no Vercel, sem preview nem check obrigatório (AGENTS §10 pede gates de release).

## Decisões
- O PRD só é escrito no repo. Pasta e Doc no Claude são só leitura (feito fora do repo a 2026-10-29).
- O PRD só muda em alterações só de documentação com `docs/changes/CHG-NNN.md`. O CI `PRD guard` verifica.
- `main` protegido: merge só por PR, com checks obrigatórios. **Sem aprovação humana obrigatória**: a sessão faz merge sozinha quando os checks estão verdes e o preview foi verificado.
- Migrações Supabase seguem expandir/contrair, para a base em produção nunca partir o código que está no `main`.

## Impacto (PRD §33 / AGENTS §15)
Papéis, workspaces, capability keys, dados, API, RLS, storage, realtime, jobs, eventos: **nenhum**. Só CI, instruções aos agentes e definições do repo.
Falhas possíveis: hotfix mais lento (PR + checks, alguns minutos); migração aplicada antes do merge do código correspondente (mitigado pela regra expandir/contrair).
Rollback: desligar a regra de proteção do `main`, apagar `.github/workflows/prd-guard.yml` e `scripts/ci/check-prd-change.sh`, reverter as linhas do `CLAUDE.md`.

## Ficheiros a criar ou alterar no repo

2. `.github/workflows/prd-guard.yml` (novo).
3. `docs/changes/CHG-000.md` (este ficheiro, cópia).
4. `docs/adr/ADR-0004-fonte-unica-do-prd-e-trabalho-por-pr.md`: decisão, alternativa rejeitada (push direto com guard só a avisar; PR com aprovação humana obrigatória, rejeitada por tornar o Tomás gargalo), trade-offs acima.
5. `CLAUDE.md`: acrescentar no fim:

```markdown
## Change workflow

- Never push to `main`. Work on a branch (`w<N>-<id>-<slug>` for features, `docs/chg-NNN` for docs), open a PR, wait for all checks and the Vercel preview, verify the preview, then merge it yourself. No human approval is required unless the task says so.
- The PRD is only edited in docs-only PRs that add the matching `docs/changes/CHG-NNN.md` (CI: PRD guard). During an implementation task never edit the PRD: if the task needs a PRD change, stop and ask for a product decision.
- Supabase migrations follow expand/contract: a migration applied before its PR is merged must be backward-compatible with the code on `main` (additive only). Destructive steps (drop, rename, tighter constraints) go in a later migration, after the code that stops depending on the old shape is merged. Commit every applied migration to `supabase/migrations/` in the same PR.
```

6. `docs/CHANGELOG.md`: entrada "CHG-000: PRD com fonte única; CI `PRD guard`; `main` protegido (merge por PR com checks obrigatórios); regra expandir/contrair para migrações. ADR-0004."

## Definições no GitHub (depois do merge deste PR)
Settings → Branches → Add branch ruleset (ou classic rule) para `main`:
- Require a pull request before merging: **sim**. Required approvals: **0**.
- Require status checks to pass: **sim**, escolher `prd-guard` (só aparece depois de ter corrido uma vez) e o check do Vercel.
- Block force pushes e restrict deletions: **sim**.
- Bypass: deixar o dono poder contornar só para emergências; as sessões não o fazem (regra no CLAUDE.md).

No Vercel, confirmar que os Preview Deployments estão ligados para branches que não sejam `main` (vêm ligados por defeito).

## Como aplicar
1. Esperar que a tarefa em curso feche (relatório §13, CHANGELOG, sem branch aberta).
2. Sessão nova no repo, com esta pasta `CHG-000/` anexada: "Aplica o pacote CHG-000. Só documentação e CI, branch `docs/chg-000`, sem tocar em código da app. Copia os ficheiros indicados, escreve o ADR-0004, acrescenta a secção ao CLAUDE.md e a entrada no CHANGELOG. Abre o PR, confirma `prd-guard` verde e faz merge."
3. Ligar a proteção do `main` no GitHub (secção acima). É o único passo manual.
4. Correr `bash sincronizar-do-repo.sh` na pasta Clipping App.
