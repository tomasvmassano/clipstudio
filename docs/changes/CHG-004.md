# CHG-004 · Registo de estado por requisito e revisão diária

**Estado:** aplicado no PRD (PR `docs/chg-004`); implementação no PR do registo (`docs/status.md`, `scripts/status/`, CI) · **Owner:** Tomás · **Data:** 2026-10-29
**Tipo:** processo de entrega. Altera PRD §33 e §36; AGENTS §3 e §13; CLAUDE.md.

## Problema
Pontos do W1 ficaram por fazer e avançou-se para outras tarefas sem dar por isso. O estado vivia espalhado pelos relatórios de fim de tarefa, pelo CHANGELOG e pela memória da conversa, que se perde quando é resumida. O Tomás pediu que deixe de haver perdas de memória e que haja uma análise recorrente do que está feito, do que falta e do que está pendente.

## Decisões (Tomás, 29/10)
1. Registo único `docs/status.md`, uma linha por ID do PRD, validado no CI contra o PRD.
2. Cada tarefa começa pelos pendentes abertos e acaba a atualizar o registo; PRs da app sem atualização são recusados.
3. Adiamentos por decisão ficam registados como `adiado`.
4. Revisão automática **diária** numa sessão independente, com relatório para o Tomás. Na fase inicial avaliou-se de hora a hora; ficou diária, porque o CI já obriga a manter o registo em cada PR e de hora a hora repetiria o mesmo relatório na maior parte das horas.

## Impacto (PRD §33 / AGENTS §15)
Sem papéis, capacidades, dados nem RLS. Processo: novo passo no CI `Qualidade`; as alterações ao PRD feitas noutro chat passam a correr `python3 scripts/status/check.py --fix` no mesmo PR quando acrescentam IDs.
Rollback: reverter este pacote, o PR do registo e apagar a tarefa agendada.

## Aceitação
`docs/status.md` com os 263 IDs atuais, semeado por uma auditoria independente; CI verde; tarefa agendada criada e a primeira revisão entregue.
